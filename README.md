# 🤝 Contributing

Black Halo Syndicate is built through collaboration.

Contributions can take many forms:

* Code
* Design
* Writing
* Research
* Documentation
* Testing
* Project management
* Business development
* Ideas
* Feedback
* Community support

Members contributing to a project should coordinate with the relevant project or division lead before making significant changes.

### Basic Contribution Flow

```text
Find a Project
      ↓
Read the Documentation
      ↓
Discuss the Contribution
      ↓
Create / Improve
      ↓
Submit Changes
      ↓
Review
      ↓
Merge
```

For technical projects, contributors are encouraged to use branches and pull requests rather than modifying the main branch directly.

---

# 🌐 GitHub Workflow

BHS repositories should generally follow a structured development workflow.

### `main`

Contains stable and production-ready work.

### `develop`

Used for active development and integration when a project requires a separate development branch.

### Feature Branches

Used for individual features, fixes, experiments, or documentation.

Examples:

```text
feature/login-system
feature/dashboard
feature/mobile-navigation
fix/responsive-layout
docs/project-guide
```

### Pull Requests

Significant changes should be submitted through Pull Requests when practical.

A Pull Request should explain:

* What was changed
* Why it was changed
* What files were affected
* Whether testing was performed
* Any known issues

# 📜 Code & Project Standards

Projects should aim for:

* Clear documentation
* Readable code
* Consistent naming
* Organized files
* Meaningful commits
* Proper version control
* Secure development practices
* Respectful collaboration

### Never commit sensitive information

```text
API keys
Passwords
Private tokens
Database credentials
Personal information
Private configuration files
```

Use environment variables and appropriate secret-management practices instead.
